# TreyOS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace tyadon.github.io with TreyOS, a 1-bit retro desktop where each part of Trey's life is an app, plus a Markdown blog with real post URLs, a Supabase guestbook and hit counter, served at https://treyyadon.space.

**Architecture:** Jekyll site built by GitHub Pages (legacy builder, Jekyll 3.10 compatible Liquid only). All copy and data live in one file, `_data/content.json`; Liquid renders it as a no-JS fallback and embeds it as JSON for the desktop. The desktop is vanilla ES modules: a small window manager, an app registry, one module per app. Pure logic sits in `*-core.js` / `lib/` modules with no DOM access at import time so `node --test` can test it. Guestbook and hit counter call Supabase RPC functions over `fetch` (no SDK).

**Tech Stack:** Jekyll (local: `/opt/homebrew/opt/ruby/bin` + `~/.gem/ruby/4.0.0/bin`, jekyll 4.4.1; prod: GitHub Pages), jekyll-feed, jekyll-seo-tag, vanilla JS (ES2022 modules), CSS, Node 26 `node --test`, Python 3 + PIL for image prep, Supabase CLI 2.115, Vercel CLI 63 (DNS), `gh`.

**Spec:** `docs/superpowers/specs/2026-11-05-treyos-design.md` (read it; this plan argues from it). Source text for posts: `docs/superpowers/specs/linkedin-posts.md`.

## Global Constraints

- No em-dashes anywhere: copy, code comments, commit messages.
- Never invent a fact, number, name, date or quote. Copy is written only from the spec's "Facts to write from". All drafted prose goes through the `humanizer` skill before Trey sees it. No sales register.
- Never on the site: OpenAI or current employer, Schyler, sports betting, internships (GE Aviation, JPMorgan Chase, Microsoft 2015), Trey's age, the Photos album names.
- No real-OS branding (no Apple logo, "Macintosh", Windows logos). The system is "TreyOS".
- Email link: itstreyyadon@gmail.com. LinkedIn: https://www.linkedin.com/in/ryadon. GitHub: https://github.com/tyadon.
- Brand colors inside project windows: Who's Got It `#0a8f63`, Pour Memory `#74291e`.
- Canonical / OG base URL: `https://treyyadon.space`.
- `docs/`, `.superpowers/`, `tests/`, `scripts/`, `supabase/`, `package.json` are excluded from the Jekyll build.
- Every published image is resized and has all EXIF/GPS stripped.
- `prefers-reduced-motion: reduce` disables boot and decorative animation. Sounds default off.
- Fonts: Google Fonts only (IBM Plex Mono, VT323). No other third-party scripts besides Supabase REST calls.
- Nothing is pushed to `main` until Trey approves a local preview (Task 11).
- Run Jekyll locally with `scripts/serve.sh` / `scripts/build.sh` (they set PATH to the Homebrew Ruby + user gem bin).

## Review Focus

1. **Phone width (375x812):** every app opens full-screen with a visible close bar, no horizontal page scroll, icons in a grid, no drag. Test in Task 5 and the Task 11 walkthrough.
2. **Supabase unreachable or paused:** guestbook shows a retro "line busy" message and the counter shows `------`; nothing else breaks and no uncaught errors. Test in Task 10.
3. **Storage throws (private mode, blocked site data):** prefs and once-per-session hit logic fall back silently. Test in Task 8 (`prefs`) and Task 10 (`shouldCountHit`).
4. **Hostile guestbook input:** HTML/script in name or message renders as text; >500-char message, empty fields, filled honeypot, `javascript:` website, and more than 3 posts per hour from one IP are rejected server-side. Tests in Tasks 6 (`esc`) and 10 (SQL + curl).
5. **Bad entry points:** unknown or malformed hash (`#/app/<script>`, `#/app/nope`) opens nothing and the desktop still boots; with JS disabled the fallback shows ReadMe, projects, latest notes and contact links. Tests in Tasks 5 and 9.

### Task 10: Supabase guestbook and hit counter

**Files:**
- Create: `supabase/migrations/0001_guestbook_hits.sql`, `supabase/config.toml` (via `supabase init`), `assets/js/config.js`, `assets/js/services/guestbook.js`, `assets/js/apps/guestbook.js`, `scripts/verify-supabase.sh`, `tests/guestbook.test.mjs`
- Modify: `assets/js/main.js` (hit counter), `assets/js/apps/index.js`, `assets/css/treyos.css`

**Interfaces:**
- Project: `supabase projects create treyos --org-id vercel_icfg_DJXK7mQboM55mdIpFwlbXFWW --region us-west-1 --db-password <generated>`. Save the password to `~/.config/treyos/supabase.env` (chmod 600, outside the repo). **If creation fails for plan limits, stop and ask Trey.** Do not touch `supabase-splititnow` or `legwork`.
- SQL (schema `public`, RLS enabled on every table, no table policies, so anon cannot read or write tables directly):
  - `guestbook(id bigint identity pk, name text not null check (char_length(name) between 1 and 40), message text not null check (char_length(message) between 1 and 500), website text check (website is null or website ~ '^https?://'), created_at timestamptz default now())`
  - `hits(id int pk default 1 check (id = 1), count bigint not null default 0)` seeded with one row.
  - `guestbook_rate(ip_hash text, at timestamptz default now())`; rows older than 1 hour deleted on each insert.
  - `sign_guestbook(p_name text, p_message text, p_website text, p_hp text) returns guestbook` security definer: raises if `p_hp <> ''`, trims inputs, rejects a small profanity word list, hashes `split_part(current_setting('request.headers', true)::json->>'x-forwarded-for', ',', 1)` with `sha256` and a constant salt, raises if 3 or more rows for that hash in the last hour.
  - `list_guestbook(p_limit int default 50) returns setof (id, name, message, website, created_at)` newest first, `p_limit` capped at 100.
  - `hit() returns bigint` (atomic increment, returns new count); `hit_count() returns bigint`.
  - `grant execute` on the four functions to `anon`; revoke all on tables from `anon, authenticated`.
- `config.js` exports `SUPABASE_URL`, `SUPABASE_ANON_KEY` (publishable anon key, expected in client code).
- `services/guestbook.js`: `validateEntry({name, message, website, hp}) -> {ok: boolean, error?: string}` (mirrors the SQL limits); `fetchEntries(limit = 50) -> Promise<Entry[]>`; `signEntry(entry) -> Promise<Entry>`; `shouldCountHit(storage) -> boolean` (true the first time in a session, false after; false if storage throws, so a broken storage never double-counts); `recordHit() -> Promise<number|null>`; `getHits() -> Promise<number|null>`.
